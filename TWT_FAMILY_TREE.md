A load-bearing pick enters this tree IN THE SAME PASS it is made: its node records the MENU
it was picked from, WHY (the named result that needs it), the REVERT CLAUSE (what un-picks
it and what falls), and WHAT RIDES it. CORE-touching picks require the coordinator's
plain-language sign-off BEFORE the pick; all others proceed on the recorded node. Stamps
per RUL-047's vocabulary: CORE / ENDORSED / PINNED / HELD / REFUSED.

## Branch protocol (standing)

When a branch point presents itself — a new pick needed, or an existing pick challenged —
the agent ADDS THE NODE HERE (menu + pick + why + revert) in the same pass, gives the
coordinator the plain-language one-paragraph version, and: CORE-touching → waits for
sign-off; otherwise → proceeds on the recorded node. A second instance (V4, a branch
sibling of V3) begins as a new BRANCH table beside V3's, inheriting the root and diverging
at named nodes — that is what "a family of candidates" looks like in the file system.
